# Проектирование серверной логики

## 1. Общая информация

Система предназначена для создания тестов, организации тестирований, назначения участников и сохранения результатов прохождения.

Основная серверная логика включает следующие процессы:

- Создание вопросов различных типов.
- Формирование тестов из вопросов.
- Формирование тестирований из тестов.
- Публикация и архивирование тестирований.
- Назначение участников на тестирования.
- Проведение тестирования и сохранение ответов.
- Проверка ответов и формирование результатов.

## 2. Создание вопросов

При создании вопроса указывается его тип, от которого зависит способ хранения данных.

Для каждого типа вопроса предусмотрена отдельная таблица для хранения соответствующих данных.

| Тип вопроса | Таблица для хранения данных |
|---|---|
| Ввод значения | `AnswerOptions` |
| Выбор варианта ответа | `AnswerOptions` |
| Выбор нескольких вариантов ответа | `AnswerOptions` |
| Сопоставление | `MatchingItem` |
| Установление последовательности | `OrderingItem` |
| Параметризованная задача | `ParameterizedTask` |

После создания вопроса соответствующие данные записываются в таблицу, предусмотренную для его типа.

## 3. Создание теста

Тест представляет собой набор вопросов, объединённых в одну сущность.

После создания вопросов они связываются с тестом посредством соответствующей таблицы связей.

Таким образом, формируется структура теста, содержащая необходимый набор вопросов.

**Результат:** создан тест, состоящий из выбранных вопросов.

## 4. Создание тестирования

Тестирование представляет собой сущность, объединяющую один или несколько тестов.

Для связи тестирования с тестами используется промежуточная таблица `TestingTest`.

В ней хранится информация о составе тестирования, порядке прохождения тестов и дополнительных параметрах, например ограничении времени и проходном балле.

**Результат:** создано тестирование, содержащее необходимые тесты.

## 5. Публикация тестирования

У тестирования предусмотрено три статуса:

- `project` — проект. Тестирование находится в процессе подготовки и недоступно участникам.
- `published` — опубликовано. Участники могут записываться на тестирование и проходить его.
- `archived` — архивировано. Тестирование больше не предназначено для новых прохождений.

Переход тестирования в статус `published` делает его доступным для прохождения.

### Запись участников

Записать участника на тестирование могут:

- Сам участник — самостоятельно.
- Администратор — назначив участника вручную.

Все записи на тестирования хранятся в таблице `TestAssigments`.

В данной таблице также хранится информация о текущем тесте, который проходит участник в рамках назначенного тестирования.

## 6. Проведение тестирования

После назначения участника на тестирование ему становится доступно прохождение тестов, входящих в состав данного тестирования.

В процессе прохождения участник отвечает на вопросы. Способ предоставления ответа определяется типом вопроса.

Ответы сохраняются в отдельных таблицах в зависимости от типа вопроса.

## 7. Проверка и сохранение ответов

Для хранения результатов прохождения используются две основные таблицы:

### ResultTest

Таблица `ResultTest` предназначена для хранения общих результатов прохождения теста.

### UserAnswers

Таблица `UserAnswers` предназначена для хранения информации об ответах пользователя на конкретные вопросы.

### Хранение ответов

Сами ответы хранятся в отдельных таблицах в зависимости от типа вопроса:

| Тип вопроса | Таблица |
|---|---|
| Ввод значения | `AnswerOptions` |
| Выбор варианта ответа | `AnswerOptions` |
| Выбор нескольких вариантов ответа | `AnswerOptions` |
| Сопоставление | `MatchingItem` |
| Установление последовательности | `OrderingItem` |
| Параметризованная задача | `ParameterizedTask` |

Таким образом, `UserAnswers` обеспечивает связь ответа пользователя с конкретным вопросом, а специализированные таблицы хранят данные, необходимые для представления и проверки ответа.

## 8. Общая последовательность работы системы

Основной сценарий работы серверной логики:

1. Создание вопросов с указанием типа ответа.
2. Сохранение данных вопросов в соответствующих специализированных таблицах.
3. Объединение вопросов в тест.
4. Объединение тестов в тестирование.
5. Публикация тестирования.
6. Запись участников на тестирование.
7. Прохождение участниками назначенных тестов.
8. Сохранение ответов в `UserAnswers` и специализированных таблицах.
9. Проверка ответов.
10. Формирование и сохранение результатов в `ResultTest`.

## 9. Основные таблицы системы

| Таблица | Назначение |
|---|---|
| `AnswerOptions` | Данные для вопросов с вводом значения и выбором вариантов ответа |
| `MatchingItem` | Данные для вопросов на сопоставление |
| `OrderingItem` | Данные для вопросов на установление последовательности |
| `ParameterizedTask` | Данные параметризованных задач |
| `TestingTest` | Связь тестирования с входящими в него тестами |
| `TestAssigments` | Записи участников на тестирования и информация о текущем тесте |
| `UserAnswers` | Ответы пользователей на конкретные вопросы |
| `ResultTest` | Итоговые результаты прохождения тестов |
